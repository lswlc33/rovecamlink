## 目标（两条验收线）

- **A. 同族新机型**（再来一台 Hi35xx / 又一型号）：零代码。这条今天已成立，只补一个型号名撞名的测试。
- **B. 全新品牌/协议族**：只加「插件 + 注册表一行 + 2 个枚举值」，不改任何现有分支，且**不改变现有机型的任何匹配结果**。

四个阶段彼此独立、可单独编译通过。阶段 1–3 做完，B 这条线就成立了；阶段 4 清掉最后两处品牌硬编码。

## 阶段 1 — 「相机像不像」不再靠共享表（纯并集，零回归）

勘查有个反直觉结论：`DEFAULT_PREFIXES` 与插件的 `wifiSsidPrefixes` **回答的是两个不同问题**。前者是「像不像相机」（列表要不要显示、要不要自动连），后者是「哪家插件认得这个名字」（给固定 IP / 出厂密码提示）。XTU 插件的注释明确说明它**故意不认领裸 `XTU` 前缀**（Ambarella 机型同名但不答 CGI），而 `DEFAULT_PREFIXES` 里的 `XTU` 正是靠宽匹配让 XTU 自己的热点被认出来。所以不能「用注册表替换」，否则反而丢掉现有识别。

改法是**合并**，且新品牌永远不必再动共享表：

1. `core/protocol/CameraProtocol.kt`：`CameraProtocolRegistry` 增加 `claimedSsidPrefixes`（汇总所有插件的 `wifiSsidPrefixes`，`bySsidPrefix` 目前是私有）。
2. `core/wifi/WifiController.kt`：新增纯函数 `fun cameraLikePrefixes(claimed): List<String> = (claimed + DEFAULT_PREFIXES).distinct()`；`DEFAULT_PREFIXES` 的注释改写为「通用兜底，新品牌请声明自己的 `wifiSsidPrefixes`，不要再往这里加」。
3. `AppGraph.kt`：增加 `val cameraSsidPrefixes = cameraLikePrefixes(registry.claimedSsidPrefixes)`（构造顺序已满足，`registry` 在 `wifi`/`scanner` 之前）。
4. 四个消费点改读它：`AppState.kt:649`（自动连触发）、`AppState.kt:797`（`joinedCameraNetwork`）、`NearbyController.kt:174`（显式传 `prefixes=`）、`AppState.kt:1038`（adopt）。
5. `WifiScanner.adoptCurrentNetwork` 增加 `prefixes: List<String> = DEFAULT_PREFIXES` 参数（接口 + 3 个 actual；desktop/iOS 只需补签名）。**已核对**：`WifiController.android.kt:208` 的内部回退传 `force = true`，而 `force` 会绕过前缀判断，所以那一处无需改。

合并是超集，**任何现有机型的匹配结果都不会减少**。

测试（commonTest，纯函数）：`cameraLikePrefixes` 并集与去重；`claimedSsidPrefixes` 最长前缀优先（`XTUCam_` 胜 `XTU`）且覆盖每个插件声明。

## 阶段 2 — 给探测优先级加护栏（含唯一一处判定变更）

6. `DeviceDiscovery.identify`：每个 `probe` 包一层 `withTimeoutOrNull(PROBE_TIMEOUT_MS = 4000)`。现在一个慢探测能吃光整个 host 预算（首台 12s），让一台已适配的相机在那台 host 上「消失」。
7. **收紧 TUWIN 的 probe**（唯一会改变判定的改动）：现在是 `contains("status") || startsWith("{")`，而 iCatch Qz 的 `/app/getdeviceattr` 正好回 `{"result":…,"info":{"ssid":…}}`——以 `{` 开头，**会被 TUWIN 抢走**。改为：解析成 JSON 对象且含它真正读取的键（`status`/`record`/`mode`/`battery`/`recordtime`），新增纯解析器 `TuwinStatus.looksLike` 放 `brand/tuwin/`，按仓库既有风格用字符串字面量单测。风险说明：TUWIN 无真机可验，但该改动比现状更严格，且不影响 XTU（Hisilicon 排第一，先认领）。
8. desktopTest 新增 `ProbeExclusivityTest`：用 `com.sun.net.httpserver`（`DiagHttpTraceTest` 已在用这个模式，`ktor-client-mock` 在离线环境不可用）按各自路径回放四家报文，断言每个插件只认领自己那家、拒绝兄弟家的报文。第 7 条修的就是这个测试会红出来的误认。
9. commonTest 新增 `CameraProtocolRegistryTest`：`associateBy` 会**静默丢弃**同 platform 的重复插件——断言 `all().size` 等于注册数量；另测顺序即优先级、`forSsid` 最长前缀、`DevicePlatform.entries.contains`。

## 阶段 3 — 能力旗标替代平台特判

10. `CameraProtocol` 增加 `supportsCameraWifiRead`、`supportsAccessPoint`（默认 `false`），`HisiliconProtocol` 置 `true`；`AppState.canReadCameraWifi():1862`、`canRaiseAccessPoint():2025` 改为问插件，不再写死 `platform == HISILICON`。
11. `CameraProtocol` 增加 `otaTransport: OtaTransport?`（默认 `null`），`HisiliconProtocol` 自己组装 `ChainedOtaTransport(listOf(XtuSocketOtaTransport(tcp, http), HisiliconOtaTransport(http)), preHandshakeFailures = 5 个 ERR_*)`——插件已持有 `http` + `tcp`，顺序与 `AppState.kt:2396-2408` 现状完全一致。
12. `AppState.startInstall` 改用 `proto.otaTransport`；`firmwareUpdateSupported():2195` 改为 `protocol?.otaTransport != null`，去掉 `platform == HISILICON`。

## 阶段 4 — 清掉两处品牌硬编码

13. `HiFiles` 从 `brand/xtu/` 移到 `core/model/`（纯解析器，只依赖 `FileType` 与 `kotlinx.datetime`）：改 `IcatchHttpProtocol.kt:3` 的 import（这是全仓唯一的跨插件依赖），`HiFilesTest` 跟着移动并改包名。
14. BLE 特征 UUID 从平台层移进 profile：`BleCameraProfile` 增加 `characteristicUuid: String? = null`（默认 `null` 是加法安全的，`XtuBleProfile` 是唯一实现者）；`XtuBleProfile` 声明 `00008888-…`；Android `wakeAndFetch` 把它传进 `GattSession`（profile 在该处就在作用域内），`discovered` 的两个分支改用该字段、为 `null` 时跳过，通用 CCCD/可写兜底保留。对 XTU 行为完全不变，但**无真机可验证**，这是本方案风险最高的一条。
15. `ui/DeviceCatalog.kt:55-57` 那句「iCatch 平台还没有插件」已过期（`IcatchHttpProtocol` 已注册），改注释。

## 明确不改（附原因）

- **`ui/DeviceCatalog.kt`、`docs/03`、`docs/index.html` 三份机型表仍需人工同步**：是文档，不是代码耦合。
- **`FirmwareUpdater` / `GkuFirmwareIndex` / `FirmwareImage` 仍是 XTU 云索引 + XTU 头格式**：要把它做成插件能力，得先有第二个家族的真实固件格式作设计依据，现在做属于凭空猜。阶段 3 只把**送包通道**挪到插件，并在接口 KDoc 里写明这个边界。
- **`MenuCatalog` 的 XTU 菜单词表**：设计上已是纯展示兜底（未知项回落固件原文、绝不隐藏），不是耦合。
- **`CameraPreview.android.kt:358` 对所有 RTSP 强制 RTP-over-TCP**：新品牌若要 UDP，需要新的覆盖点，属于播放器能力而非协议能力。
- **新增品牌仍需加 2 个枚举值**（`DevicePlatform`/`Brand`）+ `AppGraph.protocolList` 一行：加法，已确认全仓没有任何对这两个枚举的 `when` 穷举分支，所以不会强制别处改动。
