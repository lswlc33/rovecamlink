# fakecam — 给 UI 测试模式喂真图

UI 测试模式（设置 → 软件 → UI 测试模式）用一台内置假相机把每个页面填满，好让布局在
没有相机的情况下能被看见。但有一件事它原本做不到：**画廊/列表里的缩略图永远是类型
占位图标**。原因是 `loadThumbnail` 会去拉同名 `.THM`，而假相机的文件 URL 指向
`ui.test` 这个不存在的名字，请求必然失败。

这套工具补上那一步：在宿主机起一个 HTTP 服务，提供一棵**和 `UiTestDevice.files()`
一一对应**的 DCIM 树，缩略图是真实图片字节。于是画廊里每个格子画的都是真图，滚动、
缓存、分组、排序都能当真验证。

## 三个部件

| 文件 | 作用 |
| --- | --- |
| `generate.py` | 生成 `DCIM/<yyyyMMddHHmmss>/<name>` 与同名 `.THM`。图片带大号编号、日期、文件名和播放角标，**用来一眼判断某格画的是不是正确的那张图** |
| `serve.py` | 把这棵树用 HTTP 发出去，并把**每个请求**打到标准输出。格子空白时先看这里：没有日志行＝App 根本没发请求；404＝发了个树里没有的路径 |
| `../…/UiTestDevice.kt` | 假相机的文件 URL 指向 `http://10.0.2.2:18080/DCIM` |

## 跑起来

```bash
# 1. 依赖（隔离环境，不污染系统 python）
python -m venv <env> && <env>/Scripts/pip install pillow

# 2. 生成素材
<env>/Scripts/python.exe tools/fakecam/generate.py

# 3. 起服务（前台跑，日志直接看）
<env>/Scripts/python.exe tools/fakecam/serve.py
```

服务必须绑在 `0.0.0.0`，模拟器才连得上。

## 为什么是 `10.0.2.2`

模拟器的用户态网络把宿主机映射成 `10.0.2.2`（模拟器自己是 `10.0.2.15`）。这不是
MuMu 特有的，标准 QEMU/AVD 网络都是这个约定。

验证通路（模拟器里没有 curl，用 `nc`）：

```bash
adb shell "echo -e 'GET /DCIM/20260921143022/2026092114302200.THM HTTP/1.0\r\n\r\n' | nc 10.0.2.2 18080"
```

应回 `200` 和 `Content-Length: 13930` 之类。

## 素材长什么样

六条，覆盖两天的分组、照片与视频两种类型：

| 编号 | 文件 | 类型 |
| --- | --- | --- |
| 1 | `2026092114302200.MP4` | 视频 |
| 2 | `2026092114315500.JPG` | 照片 |
| 3 | `2026092118041100.MP4` | 视频 |
| 4 | `2026092209120300.JPG` | 照片 |
| 5 | `2026092209121900.JPG` | 照片 |
| 6 | `2026092219384700.MP4` | 视频 |

`.THM` 是 320×320 JPEG，13–15 KB —— 刻意落在真实 S7PRO 实测的 6–28 KB 区间里，
这样 `MAX_THUMBNAIL_BYTES`（1 MiB）和 `getBytes` 的分块读取走的都是真实路径，
而不是一个碰巧通过的尺寸。

## 排错顺序

1. **服务日志是空的** → App 没发请求。查 `AppState.loadThumbnail` 的前三行守卫
   （`protocol` / `session` / `sessionScope`）。`sessionScope` 尤其容易漏：它在
   `connect()` 里建，UI 测试模式是另一条路径，早期版本没建，于是函数第二行就返回，
   连日志都不会有。
2. **日志有 404** → 文件名或 `yyyyMMddHHmmss` 的戳对不上，对照 `UiTestDevice.files()`。
3. **日志有 200 但格子还是空的** → 解码或缓存的问题，看 App 内诊断日志页的
   `PARSE`/`FILE` 标签，那里会打出失败的字节数与前 32 字节。

## 一个注意点

`UI 测试模式` 是 session 级状态，**不持久化**：App 重启后要重新打开。这是有意的
—— 它是走查布局的工具，不该在用户不知情时留在开启状态。
