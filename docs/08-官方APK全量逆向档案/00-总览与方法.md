# 08 · 官方 APK 全量逆向档案 — 总览与方法

> 这一套文档是把 `相机 app/` 里三个官方 APK **穷尽式**拆开后的证据层。
> `docs/01–07` 是结论，这里是结论背后的每一个类、每一条字符串、每一个参数值。
> 写这套档案的直接原因：之前的分析出现过「逻辑不清楚、字符串没读出来、参数值没读出来」三类问题，
> 所以这次把提取做成脚本 + 全量表格，再在表格之上写解释，任何一条结论都必须能落到 `_work` 里的某一行。
>
> 建档日期：2026-09-21／22。语料与工具版本固定，见 §2 与 `tools/re/README.md`。

---

## 2. 方法与工具链

| 步骤 | 工具 | 产物 |
|---|---|---|
| 反编译 dex → Java | jadx 1.5.6（`_work/jadx/`） | `_work/tuwin_src/`、`_work/xtu_src/`、`_work/idgo_live_src/` |
| 反编译失败兜底 | jadx `--show-bad-code` | `_work/xtu_bad/`（XTU 有 127 个类首跑报错） |
| 资源/清单解码 | jadx；TUWIN 改走 `aapt2 dump xmltree` + `aapt2 dump resources` | 见 §3 |
| 结构化提取 | 本仓库 `tools/re/`（9 个零依赖 Node 脚本） | `data/<app>/*` + `_work/re/<app>/*` |

`TUWIN.apk` 用 jadx 跑资源阶段会卡在 “Resetting disk code cache”（两种参数都一样），因此它的清单与资源值
改由 `tools/re/aapt2.mjs` 从 `aapt2` 输出反解，产出形状与另两家一致；源码仍来自 jadx。这个替代路径顺带
补上了一个能力：布局里的 `@0x7f…` 引用会回解成 `string/名字`，见 `data/tuwin/layouts.md`。

**归属判定口径**（`tools/re/lib.mjs`）：

- `OWN` — 确认的厂商包。TUWIN `com.tuwinsmart.*`；XTU `com.gku.*`、`com.icatchtek.*`、顶层 `icatch.*`、`com.example.icatch*`、`com.hisi.*`、`m.mifan.acase.*`；idGoLive `com.icatch.*`、`com.icatchtek.*`、`com.id221.*`、`com.tinyai.*`。
- `UNKNOWN` — 既不是厂商包名也不在已知库清单里（混淆后的应用层藏在这里），**与 OWN 一样逐类展开**。
- `lib` — 已确认的第三方库/平台代码，只清点不逐类分析。

这样定的理由：XTU 的 App 层重度混淆，按包名白名单会漏；宁可多展开一堆开源库，也不能把相机协议代码留在「未分析」里。
反过来说，`data/<app>/packages.md` 里每个包归哪一档都写明了，读者可以自己复核有没有把某家库误判成厂商代码。

## 5. 按问题找答案

| 你想知道 | 先看 |
|---|---|
| 某个操作官方到底发了什么 | 对应档案的「操作复现表」；再查 `catalog-http.md` / `catalog-templates.md` 拿原始模板 |
| 某个参数有哪些取值 | 对应档案的「设置项全表」；`catalog-enums.md` + `res-strings-default.md`（entries/values 成对）。注意 `catalog-settings.md` 只有 XTU 11 行 / idGoLive 9 行 / TUWIN 0 行——**这三家的设置选项绝大多数不在静态资源里，而是设备自描述**，这本身就是 `docs/03` 反复强调的那件事 |
| 某个端口/超时/缓冲区数值 | `catalog-ports.md`，再顺 `api/<包>.md` 找它被谁用 |
| 相机上报了什么事件、字段叫什么 | 对应档案的协议栈小节 + `own-literals.tsv`（scratch） |
| 页面上有哪些入口/文案 | `layouts.md` + `res-strings-zh.md` |
| Java 层看不到、藏在 .so 里的实现 | `natives-jni.md`、`natives-strings.tsv`，再回 `api/` 找调用点 |
| 某条结论有没有证据 | 档案里每条事实都带 `_work/<app>_src/sources/...:行号`；照行号读原文 |

## 6. 边界与已知空白

- **只读静态分析。** 不主动连别人的设备、不做利用；动态验证只发生在自有设备/自建模拟器上。方法声明沿用 `docs/05` §0。
- **不搬运代码。** 档案记录事实、常量、控制流描述与引用，重实现按干净室路线自己写（参见 `docs/02` 的架构约束）。
- **静态定不来的东西明确留白**，各档案末尾有「未解之谜」小节列出需要的补证手段（抓包、真机、IDA）。目前已知的硬空白：idGoLive 的 PTP-IP 端口号（3195/3196 属推测）、各家 TLS 证书固定与否的运行时行为、云端接口的真实鉴权链。
- **混淆**：XTU 的 App 层符号不可读，靠 `UNKNOWN` 桶 + 字面量反推；这会让部分「这个方法叫什么」只能回答「它在 `m/gku/xtugo/…` 的某处，做了 X」。
- **jadx 反编译失败的方法**：全语料共 58 个文件带 `JADX ERROR`，其中**厂商侧 3 个**：
  `m/mifan/acase/icatch/IcatchProtocol.java`（`getFileList(int,int)` 因 RegionMaker 溢出没出 Java）、
  `com/gku/actioncam/hisilicon/dv/dlg/DlgForProcessActivity.java`、
  `com/gku/actioncam/hisilicon/dv/localimage/ImageEditLib/ImageEditActivity.java`。
  jadx 在这些方法位置留了 smali 伪码，`tools/re/code.mjs` 会把里面的字符串与整数常量捞回来，
  在 `own-literals.tsv` 里以 `via=bytecode` 标记（例：`IcatchProtocol` 失败块里的 `playbackClient`、`listFiles(...)`、`15`）。
  其余失败文件全在 kotlinx / androidx / exoplayer / bugly / luck 等库代码里，厂商侧没有整类丢失。
  `_work/xtu_bad/`（`--show-bad-code` 版）用于对照，条目集合与 `_work/xtu_src/` 完全一致。

## 7. 与既有文档的关系

- `docs/01`（首次逆向报告）：概览，本次深挖后其结论以 08 为准；三份档案各有「对既有文档的纠正」小节。
- `docs/03`（品牌型号与协议矩阵）：结论层速查表，08 是它的证据层；08 发现的错要回写 03，不留两份互相矛盾的表。
- `docs/04`（固件与功能差距）、`docs/05`（网络 API 与安全评估）、`docs/07`（蓝牙配网与 VPN）：都从这三家取证，08 补充其取值细节并修正域名判定（反编译包里有域名字符串 ≠ 是真在用的 API）。
- 实现层（`composeApp/src/*/**.kt` 的 profile / protocol 插件）应以 08 的表为验收清单：表里每一行要么已实现，要么在 `04-三家操作对照与复现清单.md` 里被显式标记为「不做」。

## 8. 复跑

```sh
node tools/re/run-all.mjs        # 三家全跑，约 3–5 分钟
node tools/re/run-all.mjs xtugo  # 只跑一家
node tools/re/check-citations.mjs   # 校验本目录所有 `文件:行号` 引用能否定位（找不到/越界 → 退出码非 0）
node tools/re/check-links.mjs       # 校验文档之间的相对链接都指向真实存在的文件
node tools/re/check-tables.mjs …    # 校验表格列数（GFM 里裸 `|` 会把一行劈成多列）
node tools/re/canonicalize-citations.mjs <doc.md> <appKey> --apply   # 把裸文件名引用补成全路径
```

前置条件、每个提取器的输入输出、以及踩过的坑（Git Bash `unzip` 的 `*` 不跨 `/`、jadx 复制 store-only `.so`
会截断、Kotlin `@Metadata` 二进制字面量污染等）写在 `tools/re/README.md`。

引用校验不是装饰：这一轮它抓出了 4 处把 `HaisiPreviewModel.java` 误写成 `HisiPreviewModel.java`、
9 处把 jadx 内联的匿名类写成 `Foo$AnonymousClass1.java`（这种文件根本不存在）、
以及 1 处引用了从未存在的 `docs/02-功能-设备连接流程.md`。**文档里的行号必须机器核过，不能靠人眼。**
