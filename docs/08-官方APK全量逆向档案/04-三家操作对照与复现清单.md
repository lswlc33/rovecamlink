## 3. 本次深挖暴露出的「我们已经写错」的点

优先级从「不修就用不了」往下排：

1. **TUWIN 下载端点不存在。** 我们发 `GET /api/playback/download?file=<名字>`；官方目录里没有这条路径，官方下载走 `GET /api/playback/rawdata`（`StreamingTransferEngine` + `Ride3ProPlaybackDownloadResumePolicy`，见传输OTA §2）。位置：`composeApp/src/commonMain/kotlin/com/rovecamlink/app/brand/tuwin/TuwinRestProtocol.kt:169`。
2. **TUWIN 回放参数名错。** 官方按**索引**寻址：`GET /api/playback/filelist?mode=<int>&file_index=<int>`、`GET /api/playback/thumbnail?file_index=<int>`、`GET /api/playback/delete?file_index=<int>`、`GET /api/playback/pause?file_type=<int>`、`GET /api/playback/dayinfo?date=<int>`（全部在 `_work/tuwin_src/sources/com/tuwinsmart/tuwin/data/source/remote/api/ride3pro/Ride3ProApiService.java:40-72`）；我们按文件名传 `file=<名字>`。位置：`composeApp/src/commonMain/kotlin/com/rovecamlink/app/brand/tuwin/TuwinRestProtocol.kt:150,179,184`。
3. **`/11` 不是 folklore。** 我们代码注释曾写「APK 里根本没有 /11」——错，见 §2 预览行；注释已按证据改写（`HisiliconProtocol.kt` 顶部），但这提醒一类风险：**「我搜不到」不等于「没有」**，跨平台的字符串常量可能被拼出来。
4. **M3 帧模型不能按分隔符实现。** 官方活路径是「一次 read = 一帧」的 `LegacyReadChunkFrameDecoder`，`DelimitedFrameDecoder` 零构造点，`64KB/256KB` 是死代码里的常量（协议面 §4）。我们目前没有 M3 socket 实现，将来做时别照 01 报告旧行文。
5. **缺 36 个海思命令。** 机械比对结果：官方 hi3510 目录里 85 个 `.cgi`，我们用到 49 个，**我们用的 49 个全部在官方目录内**（没有凭空发明），缺的 36 个里值得优先补的是：`getcapability.cgi` / `getdevcapabilities.cgi`（能力上报，决定 UI 开关）、`deleteallfiles.cgi`、`getwifi.cgi` / `setwifichannel.cgi` / `wifisleep.cgi`、`settimerinfo.cgi`+`gettimerinfo.cgi`（定时拍）、`getburstinfo.cgi`、`getspotmeter.cgi`、`gettimeosd.cgi`、`getscreenautosleep.cgi`、`setbootaction.cgi`。

## 5. 落地顺序（只列还有价值的）

1. 修 §3 的 1、2 两条（TUWIN 端点与参数名）——但它们**必须等 TUWIN 真机**才能确认，否则就是把一个未验证猜测换成另一个。有 TUWIN R3Pro/R6 设备时一起改。
2. 补 `getcapability.cgi` 一族：这是唯一能把「UI 该显示哪些开关」从猜变成问的机会，且我们现在 XTU 侧设置项是动态菜单 + 硬编码 11 项 legacy 混合。
3. 补 `deleteallfiles.cgi`、定时拍（`settimerinfo`）、WiFi 信道：都是低成本高感知，且 XTU 真机可当场验。
4. idGoLive（iCatch/PTP）插件：**只有在拿到对应真机时才做**，因为 PTP/IP 端口静态无解（idGoLive 附录 C §3.6 给了 4 步验证法，需要先抓到设备）。
5. 其余 36 缺项按「真机用到才补」推进，不预先造 API 面。
